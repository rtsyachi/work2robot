# プロダクト定義｜Work2Robot

**状態：MVPの目標仕様（2026-11-04 改訂：ハードウェア仮選定を必須機能に追加。2026-11-05 改訂：前提のマスタ登録を追加）。実装済みの主張ではない。**

## 一文でいうと

**人間の作業動画と説明から業務を構造化し、必要なロボット構成を仮選定して仮想ロボットで業務を実行し、ロボット導入前に検討すべき改善余地と確認事項を示すプラットフォーム。**

## 課題と利用者

物流現場では、人が荷物の重量・形状・積付状況を判断しながら作業している。ロボットに置き換えようとしても、次が不明確になる。

- 人がどのような業務ルールに従って作業しているか
- ロボットにどのような動作・判断能力が必要か
- どのようなハードウェア構成なら対応できそうか
- 実際にロボットが作業すると、どのような動きになるか
- 実機導入前に何を確認・改善する必要があるか

- **主な利用者：** ロボット導入SIer・業務コンサルタント・物流拠点の管理者。
- **情報の提供者：** 作業者・現場リーダー。仕事を実演し、判断理由や例外を話す。
- **利用段階：** 実機PoC前の業務分析・自動化設計・ハードウェア検討・必要な実証条件の整理。

## ユーザー体験（前提のマスタ登録＋5つの機能）

0. **マスタ登録（前提）：** 解析・判断・選定・実行の前提となる現場のデータを最初に登録する。**荷物マスタ**（荷物ID・名称・種類・材質・重量・寸法・破損注意・取扱メモ、便＝1台に積む荷物の組み合わせ）と**環境マスタ**（積付先のカゴ車の内寸・積付高さの上限・最大積載・開口面、仮置き場（棚・パレット）の列と間隔、作業エリアの通路幅・床面）。表への入力とCSVの取り込みに対応し、登録内容は決定的なコードで検証する（エラーは保存しない。未登録の値・カゴ車に入らない荷物・積載上限を超える便は注意として示す）。以降の機能はすべて登録したマスタの値を使う。動画から重量など見えない属性を推定しないのは、この登録があるためである。
1. **作業動画・説明音声の入力：** 人がカゴ車へ荷物を積む動画と、作業中の判断理由の説明（自然な口語）を入力する。
2. **業務ワークフローの抽出：** Claudeが動画と音声を解析し、業務全体（Level 1：開始・繰り返し・終了条件・業務の規則）、荷物1個の判断（Level 2：条件・分岐・例外）、基本動作（Level 3：Pick/Move/Place）、根拠（動画の場面・発話）、不足情報・曖昧な条件を構造化する。映像の観測・発話・模擬マスタ・AIの推定を区別する。
3. **ロボットハードウェアの仮選定：** 業務から必要な能力（可搬重量・大きさ・リーチ・把持の種類・回転・計測など）を導き、模擬の部品一覧から構成（移動方式・アーム・手先・センサー・周辺設備）をClaudeが選定理由つきで提案する。仕様の照合は決定的なコードで行い、未確認の能力は未確認のまま実機PoCの確認事項へつなげる。
4. **仮想ロボットによる業務実行：** 仮選定した構成を前提に、カゴ車1台分の混載荷物を連続処理する。能力が足りない荷物は持ち上げずに人へ引き継ぎ、届かない位置には置かない。すべての動きは実行トレースから再生し、業務ワークフローと連動表示する。
5. **改善余地・確認事項：** 業務理解・ハードウェア選定・仮想実行を統合し、改善余地（作業順序・積付パターン・ロボット構成・周辺設備・運用。すべて仮説）と確認事項（曖昧な業務ルール、不足情報、センサーで取得できるか未確認の情報、把持・リーチ・干渉・安全の実機検証、PoC項目）を示す。

## MVPの対象と非対象

**対象：** 物流センターでのカゴ車への混載荷物の積付。1便分（15〜20個）の段ボール・ソフトバッグ等を扱う。業務の規則（重い順・レンガ積み・偏荷重・上積み厳禁・上限・はみ出し確認）と荷物ごとの分岐を含むワークフロー、模擬の部品一覧からのハードウェア仮選定、その構成での仮想実行と導入前評価が主要成果。

**対象外：** 実在ロボットの詳細な機種比較・選定保証、高精度な運動学・物理シミュレーション、実機ロボットの動作制御、VLAの学習、本格的なROI・投資回収の試算、最適化アルゴリズムによる作業改善の自動反復、複数の業務シナリオへの対応、実機の安全認証、本番WMS連携、導入後OJTの継続運用基盤。

**重要：** 現場における「何を、いつ、どの条件で」の知識（業務ワークフロー）と、ロボットの能力（ハードウェアの能力プロファイル）を**分離して管理**し、同じ業務を異なる構成で評価できるようにする。VLAやロボット制御が担う下位動作は、今回の試作では**模擬スキル**として扱う。

## 確実に伝える価値

- **可視化：** 1本の作業動画・説明から、判断を含む業務ワークフローが見える。
- **構成の検討：** 業務から必要な能力と仮のロボット構成が見え、構成を替えると仮想実行の結果が変わる。
- **PoC準備：** どの情報・能力・安全条件を実機で確認すべきか明らかになる。

「自動化できる」と断言するのではなく、**自動化に向けて、どんな構成で何を実証すればよいかがわかる**ことを現時点の製品価値とする。
