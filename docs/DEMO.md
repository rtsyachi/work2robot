# 3分デモ台本・絵コンテ｜Work2Robot

**状態：収録の目標仕様。映像の成功を保証するものではない。**

## 核になるメッセージ

**Human Work → Workflow → Robot Work → Automation Readiness。** 人がカゴ車に荷物を積む動画と説明から、Claudeが業務を条件分岐付きワークフローとして理解し、仮想ロボットが同じ業務を実行する。実機導入前に、自動化できそうな範囲と課題を明らかにする。

主役は**人の作業動画と、仮想ロボットが同じ業務を行う様子の対比**。人の動画・ワークフロー・仮想ロボットを同じ画面に並べ、実行中のステップと分岐を連動させる。スライドによる長い説明は使わずアプリの実演を中心にする。

## 映像で特に見せる条件

- 入力動画・説明の要件と制作方針は `docs/DEMO_INPUT.md` を正本とする。導入用の実写素材と、アプリが解析する模擬作業動画を混同させない。
- 模擬動画での成功を、実写動画での認識性能や実機の動作保証として説明しない。
- 動画中に一度しか通っていない作業から、未実演の分岐を観測済みとして扱わない。説明テキストから追加した分岐と分ける。
- 判断基準の数値（底面0.15平方メートルなど）は、提供した説明テキストが根拠であることを表示し、Claudeが生成した値に見せない。
- Claudeとのリアルタイムな質疑応答や、回答を入力するUIはMVPの対象外。未定義の条件は確認事項として示すにとどめる。
- **決定的実行器のログが先で、画面上の分岐ハイライト・アニメーションが後。** 事前に作った映像を動的実行に見せかけない。
- APIの待ち時間を編集で短縮してもよいが、事前に用意したClaudeの文章を、その場で解析した結果のように見せない。
- 作業計画の論理検証 ≠ 実機の動作可能性。3D表示には「仮想プレビュー」を明示する。

## 素材

- 導入用の実写素材と、アプリの入力動画の候補・制作方針は `docs/DEMO_INPUT.md` を参照。
- 権利を持たない素材を公開リポジトリへ含めない。

## 時間が足りない場合の削減順

**演出・ロゴ → 複雑な3Dモデル → 根拠表示の作り込み**を削る。最後まで死守するのは**実際のワークフロー生成、複数荷物の業務実行と分岐の変化、実現性の事前チェック**。
