## 映像で特に見せる条件

- 入力動画・説明の要件と制作方針は `docs/DEMO_INPUT.md` を正本とする。導入用の実写素材と、アプリが解析する模擬作業動画を混同させない。
- 模擬動画での成功を、実写動画での認識性能や実機の動作保証として説明しない。
- 判断基準の数値（積載上限150kgなど）は、根拠（カゴ車の表示＝模擬の仕様）を表示し、Claudeが生成した値に見せない。
- 実行器が扱えない規則は「未対応」と表示し、適用済みに見せない。支持状態・重心は幾何学的な概算。
- **ハードウェアの部品一覧は模擬**（実在の機種ではない）。仕様照合は「仕様上」であり、把持力・可動域・干渉・安全性は検証していないことを画面に出す。未確認の能力を確認済みに見せない。能力が足りない荷物を何事もなく持ち上げる動きを見せない。
- 改善余地は仮説。構成を替えた再実行の差は「仮想環境での結果」とし、実証済みに見せない。
- 解析用の元動画と、提出動画に入れる短縮版の時間軸を混同させない（短縮版には元動画の時刻を表示する）。
- Claudeの結果は**保存済みの実際の応答**を表示する（画面に「保存済み」と日時を出す）。事前に用意した文章を、その場で解析した結果のように見せない。生成の様子を見せる場合は、コマンドの実行画面を短く入れる。
- **決定的な実行器のログが先で、画面の分岐ハイライト・アニメーションが後。** 事前に作った映像を動的実行に見せかけない。

**演出・ロゴ → 3Dの作り込み → 根拠表示の細部**を削る。最後まで死守するのは**実際のワークフロー抽出、ハードウェアの仮選定と照合、選んだ構成での複数荷物の業務実行（構成による結果の違い）、改善余地・確認事項**。
