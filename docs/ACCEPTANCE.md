# 受入基準・検証記録

**完成はファイルが存在することではなく、繰り返し実行できる結果で判断する。** 本ファイルには受入条件を記す。実際の検証結果は日付・コマンド・成功/失敗を追記する。

## 必須の受入条件

| ID | 完成条件 | 実証方法 |
|---|---|---|
| A01 | 作業動画と説明から、動作と判断分岐を含む構造化案が出る | 動画→観測テキスト変換の出力を使い、Claude API応答を保存して評価用正解データと比較・目視確認。固定テキストでの抽出成功は部分達成とする |
| A02 | 映像・発話・提供テキスト・模擬データ・推測・未確認を区別。分岐ノードを選ぶと根拠の動画区間・説明テキストが表示される | 出力の根拠表示と、分岐ノード選択時の表示を確認 |
| A03 | 基準が示されていない条件は「要確認」として確認事項に残り、確定した分岐として実行されない。説明にある基準（底面0.15㎡以上）は根拠付きで定義済みになり、Claudeが閾値を生成しない | 要確認の条件に当たる入力を実行し、`on_unknown`経路と確認事項の表示を確認。閾値の根拠表示を確認 |
| A04 | 生成したグラフを**同じ実行器**へ渡せる | グラフ検証、ノード参照と`on_unknown`の確認 |
| A05 | 通常の箱とソフトバッグで異なる経路を通る | 通常ケース（硬い箱・ソフトバッグ）の実行トレースを比較 |
| A06 | 壊れ物入りバッグでは押し込まずに上段へ置く経路を選ぶ（人への引継ぎにはしない） | 壊れ物ケースを実行し、スキルイベントの押込みなし指定を確認 |
| A07 | 不明属性・要確認の条件では不明経路を通り、暫定動作（動画どおり、またはAIの仮説と明示）で完了し、確認事項を残す。確定した結果とは区別して表示する | 属性不明ケース・要確認ケースを実行し、暫定動作と確認事項を確認 |
| A08 | グラフのハイライトと3D動作がトレースに連動 | 動画・スクリーンキャプチャによる確認 |
| A09 | 仮想検証の結果、確認事項（未定義の条件・不足情報）、実機の未検証事項を分けて示す | 事前チェック画面を確認 |
| A10 | 3分以内の日本語動画で一連の動作が見える | 通し録画で確認 |
| A11 | 公開GitHubに秘密情報・流用禁止データ・未許諾素材がない | `git status`、ファイル確認、起動手順確認、導入用実写素材の利用条件記録 |
| A12 | 動画生成用の台本・正解データがアプリの入力経路に入っていない。模擬素材であることが画面に表示される | 入力経路のコード確認、画面確認 |

## データ整合性の検証と実演は別

デモ用ワークフロー・入力データの**整合性検証**は、A01/A08/A09/A10の合格ではない。実装したらバックエンドの自動テスト、フロントエンドのテスト・ブラウザ確認を追加する。
